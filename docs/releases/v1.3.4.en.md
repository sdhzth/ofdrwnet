# NetOfd v1.3.4

## Patch release: fixes the "current version" marker on NuGet package pages, adds the v1.3.3 release notes

This **patch release** contains **no code changes** — documentation indexes only.

### 🐛 Fix: the "Release notes" index on NuGet package pages was stuck at v1.3.2

**Symptom**: the nuget.org page of every `NetOfd.*` package renders the README copy **bundled
inside the package**, where the "Release notes" table marked `v1.3.2` as *current* — while the
actual latest version was already v1.3.3. The package page did not match the real version.

**Root cause**: the README release-notes index hardcodes the "current version" as a literal string
and was not updated when a new version was published; on top of that, v1.3.3 had no release-notes
files of its own (`docs/releases/v1.3.3.md` / `v1.3.3.en.md`).

**Fix**:

1. The release-notes index in both READMEs (Chinese / English) now marks v1.3.4 as *current*, and
   the v1.3.3 and v1.3.2 rows were added;
2. `docs/releases/v1.3.3.md` and `docs/releases/v1.3.3.en.md` were added, covering the three main
   themes of v1.3.3:
   - **`defaults` namespace conformance** — GB/T 33190-2016 §7.1 / GB/T 48666-2026 §6.2 require the
     root node to also declare `xmlns:defaults`; new `OFDElement.InjectDefaultsDeclaration*` /
     `RestoreOfdPrefix*` / `NormalizeOfdXmlBytes`, and `EnsureDefaultsNamespace(XElement)` is
     deprecated (LINQ-to-XML cannot express two prefixes for one namespace — it rewrites the
     element prefix from `ofd:` to `defaults:`, violating §7.1);
   - **bidirectional support for page-level resources `PageRes.xml`** — GB/T 48666-2026 §7.2 a; the
     reader now supports the third resource kind the Java version skipped, the writer gains
     `MediaPlacement.Auto` / `DocumentOnly`, and `PageObject.AddPageRes` keeps `PageRes` before
     `Content` (GB/T 33190 table 13 Schema order);
   - **standard font resource naming `Font_M.ttf`** — GB/T 48666-2026 table 1.

> **Why this could not be fixed on 1.3.3**: the bundled README is a **frozen copy of the published
> version**, and NuGet does not allow overwriting a published version — so the correction can only
> reach the package pages with the next release (this v1.3.4).
